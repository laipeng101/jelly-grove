# 流转送达设计

流转送达与经典模式分别保存进度，共用音效、音量和动效设置。恢复缓存页面时应用最新设置，并保留该模式的进度。

## 一次行动的语义

目标配额按对记录。送达要求配对合法，且消除前至少一颗目标水果已在采收口。目标水果首次出现在采收口后，下一次成功配对若未送达该目标，就算错过首次窗口。连线被堵时也按到站计算。

站外可消除多余的目标水果，前提是数量仍足够完成当前及后续配额。数量不足时提示需保留多少水果，原棋盘、回合和奖励继续有效。

成功配对后，先保存快照并按原位置计入目标，再消除和执行当前阶段的位移。达成目标后先切换阶段，最后一个阶段达成即获胜。随后用当前阶段的剩余步数和可用配对判断是否失败。因此最后一步达成目标仍有效，阶段切换本身也不额外移动棋盘。多条轨道同时移动，空格随轨道移动。轨道之间无交叉，也不包含石头。

玩家可以走入死局，可用撤销或重试恢复。免费撤销覆盖整盘，通关或失败后仍可用。连消随成功配对累积，思考、暂停和后台时间均不扣减。

## 星级、提示与复盘

完成本盘目标、通关且未使用解题提示、完成专属挑战各得一颗星。棋盘上方逐项展示得星条件，默认文字至少 16 CSS 像素。对局中显示主题最佳，通关后显示本盘收获。体验完成要求每个主题至少通关一次。

自动挑战检查不算解题提示。已不可逆违反条件或完整搜索证明没有挑战路线时，显示划去的星形、原因和撤销入口。检查预算耗尽、Worker 不可用或超时时保持未确定。撤销、重试、换盘和导入后重新判定，过期结果不覆盖当前局面。

解题提示分三层。先给主题提示，再从同一个盘面对比两种配法，最后给出从初盘完成专属挑战的完整解法。对比时须交代盘面是初盘还是按步骤推演后的结果。使用解题提示会失去“不用提示”星，撤销、重试和读档都保留这条记录。阅读规则和预览下一拍仍可获得该星。预览只显示位移结果，从棋格用键盘打开再关闭时，返回原焦点并保留选择。

果汁加满时触发庆祝。撤销还原连消、分数和果汁。通关纪录取最佳单局。重试回到同一初盘，换盘则重新请求棋盘。

最后一拍反馈结束后显示收获。切换主题由玩家确认。关闭后或刷新恢复时，由玩家主动打开收获。

## 生成质量

主题名称和提示见 [themes.ts](../src/journey/themes.ts)，挑战规则见 [rules.ts](../src/journey/rules.ts)，生成准入见 [generator.ts](../src/journey/generator.ts)。

| 主题 | 必需证据 |
| --- | --- |
| 到站配对 | 首次与延后到站送达都能通关，目标初始需要推进 |
| 保留一对 | 消耗与保留指定配对会改变后续可用机会 |
| 提前开路 | 提前与延后开路结局不同，外沿路线无法绕过开路判断 |
| 同类配对 | 消耗与保留多余目标都有通关解 |
| 双轨同步 | 同步推进使两条轨道的安排相互影响 |
| 综合送达 | 能证明最低消耗，另有消耗更高的通关解，且部分选择相互影响 |

候选需要有完成专属挑战的通关解，也要有未达专属挑战的通关解。用于比较的关键分支必须是合法操作。

位置、空位、搭档关系和关键操作顺序的变化可以形成实质不同的棋盘。单纯镜像或更换水果外观的盘面归为同类。检验相关机制确为通关或挑战所必需，并允许无关配对互换顺序及多条解法。

## 生成预算

浏览器等待 Worker 生成，超过请求时限后使用按同一标准认证的备用盘，优先避开近期用过的棋盘。[生成配置](../src/journey/types.ts)定义请求时限、Worker 求解预算、每个主题的备用盘数量和近期避重范围。正式基准与生成命令见[生成专项](development.md#生成专项)。

## 布局与动效

独立 HTML 内嵌 Worker 与备用盘，支持断网冷启动。有效视口 360×640 CSS 像素、默认字号时，完整显示棋盘、目标和操作。水果及主要控件至少 44×44 CSS 像素，外沿留出连线路径。文字放大或空间不足时，目标及操作仍可滚动到达。

动效依次为连线消除、多轨同步滑动和落定。采收口固定，闲置方向提示只改变呈现。关闭动效或系统启用减少动态效果时直接显示结果。缩放、隐藏页面或换盘中断动效时，清除过渡图层并保留已提交状态。
